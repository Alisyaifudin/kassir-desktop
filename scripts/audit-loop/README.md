# Audit loop — auditor → fixer → commit

Two pi SDK agents run continuously against this repository:

1. **Auditor** reads the codebase and writes evidence-based reports under
   `audit/iterations/<NNN>/`. It scores six areas; the harness computes a
   weighted overall score and regenerates `audit/toc.md`.
2. **Fixer** reads the reports one by one, fixes them, records the outcome, and
   runs the verification command.
3. The harness commits the iteration (`chore(audit): iteration N - score X/100`),
   then starts the next audit.

The loop stops when:

- the auditor's score reaches `--target` (default **95**), or
- the score has converged: the spread over the last `--window` audits (default
  **5**) is at most `--epsilon` (default **2**), or
- `--max-iterations` is reached, or
- the fixer makes no commit twice in a row, or
- verification fails and cannot be repaired.

## Quick start

```sh
# Full loop, models resolved from ~/.pi/agent settings
bun run audit:loop

# Pick models explicitly
bun run audit:loop --model commandcode/deepseek/deepseek-v4.1-flash --thinking high

# Different models for the two roles
bun run audit:loop \
  --auditor-model anthropic/claude-opus-4-5 \
  --fixer-model anthropic/claude-sonnet-4-5 \
  --thinking high

# Audit only, no fixes or commits (works on a dirty tree)
bun run audit:once
```

Model resolution order per role:

```
--auditor-model / --fixer-model  >  --model  >  PI_MODEL  >  ~/.pi/agent settings  >  first available
```

`--provider` (or `PI_PROVIDER`) narrows the lookup.

## Flags

| Flag | Default | Meaning |
| --- | --- | --- |
| `--model <ref>` | settings | Model for both agents (`provider/id` or bare id). |
| `--provider <id>` | — | Provider hint for model resolution. |
| `--auditor-model <ref>` | — | Auditor model override. |
| `--fixer-model <ref>` | — | Fixer model override. |
| `--thinking <level>` | settings | `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`. |
| `--target <n>` | `95` | Stop at this score. |
| `--window <n>` | `5` | Number of scores used for convergence. |
| `--epsilon <n>` | `2` | Max score spread over the window. |
| `--max-iterations <n>` | `20` | Hard cap on audits. |
| `--verify <cmd>` | `bun run lint` | Run after the fixer. |
| `--no-verify` | — | Skip verification. |
| `--audit-dir <path>` | `audit` | Report directory. |
| `--agent-timeout <min>` | `30` | Wall-clock limit per agent run. |
| `--dry-run` | — | Audit only. |
| `--allow-dirty` | — | Start with uncommitted changes. |
| `--force` | — | Ignore a previous run's `finished` marker. |
| `--verbose` | — | Print full tool arguments. |

## Files

```
audit/
  toc.md                         # generated index: score, history, reports
  state.json                     # machine state (resume-safe)
  iterations/001/
    report-01-cart-rerender.md
    report-02-...
  logs/                          # git-ignored agent transcripts
    iteration-001-auditor.log.md
    iteration-001-fixer.log.md
```

`audit/toc.md` and `audit/state.json` are regenerated by the harness. The fixer
is blocked from editing anything under `audit/`; it records progress through
`record_fix`.

## Scoring

The auditor scores six areas. The harness computes the weighted total:

| Area | Weight |
| --- | ---: |
| Architecture & project structure | 15% |
| React correctness & performance | 25% |
| Tauri / Rust / desktop security | 15% |
| UI/UX & accessibility | 20% |
| Code quality & maintainability | 15% |
| Testing & tooling | 10% |

The auditor is instructed to score honestly: 100 means no meaningful issues;
95 means production-grade with minor nits. A score increase requires concrete
evidence in the code.

## Safety

- The worktree must be clean before a full run. The harness refuses to start
  otherwise, because its commit would sweep unrelated changes in. Use
  `--allow-dirty` deliberately. `--dry-run` (and `bun run audit:once`) is
  allowed on a dirty tree because it never commits.
- The auditor is read-only. It gets `read`, `grep`, `find`, `ls`, and a
  `run_readonly_command` tool that rejects mutations, redirection, chaining, and
  mutating git/package commands.
- The fixer cannot run `git add/commit/push/reset/checkout/...`, and cannot
  write to `audit/`. Both restrictions are enforced by an inline pi extension,
  not only by the prompt.
- Verification is baseline-aware. If `bun run lint` already fails before the
  run, the post-fix gate records the result but does not block commits. If it
  passed before, a regression stops the loop and leaves the changes uncommitted
  for inspection.
- `Ctrl-C` aborts the current agent, saves state, and exits. Re-run to resume.

## Resuming

The harness is resume-safe:

- Start it again and it continues from `audit/state.json`.
- If the last iteration has an audit but no fix pass, it resumes the fixer.
- If the last run finished normally, use `--force` to continue past the marker
  (for example, after manually fixing some reports).

## What gets committed

One commit per iteration, after the fixer and verification:

```
chore(audit): iteration 3 - score 74/100

Auditor score: 74/100
Reports: 6
Fixes: fixed 4, partial 1, skipped 1
...
Verification: `bun run lint` passed
```

The commit includes the source changes, `audit/iterations/003/*`, `audit/toc.md`,
and `audit/state.json`. Agent transcripts in `audit/logs/` are ignored, and the
harness excludes them from the commit even if the project does not ignore them.

When the loop stops right after an audit (target reached, convergence,
max-iterations, no-progress), it makes one final
`chore(audit): iteration N - score X/100 (final audit)` commit containing the
final reports/TOC/state. It only does this when every dirty path is inside
`audit/`, so unrelated work is never swept in.

## Tuning

- **Too many nitpicks?** Raise `--target` and tighten the auditor prompt in
  `scripts/audit-loop/prompts.ts`.
- **Converging too early?** Increase `--window`, lower `--epsilon`, or set
  `--max-iterations` higher.
- **Fixer breaking things?** Keep `--verify` (default) and make sure the
  baseline passes. The harness will send the failure output back to the fixer.
- **Expensive audits?** Use a cheaper auditor model and a stronger fixer model,
  or lower `--max-iterations`.

## Troubleshooting

- **`Working tree has uncommitted changes`** — commit or stash your work first.
  The harness refuses to run because its commit would include unrelated changes.
  `bun run audit:once` is exempt because it never commits.
- **`No models with valid credentials found`** — run `pi` once to authenticate,
  or pass `--model provider/id`. `pi` stores credentials in `~/.pi/agent/auth.json`.
- **The auditor never calls `submit_audit`** — check the transcript in
  `audit/logs/iteration-NNN-auditor.log.md`. The harness nudges three times and
  then stops. A stronger model or a smaller `--max-iterations` usually helps.
- **The fixer times out** — increase `--agent-timeout`, or use a faster fixer
  model. The fixer is instructed to record partial fixes and submit before the
  budget runs out; the next iteration starts from whatever was committed.
- **`audit/state.json` is corrupted** — move it aside. The reports on disk are
  still readable; the harness will create a fresh state and start a new iteration.
- **A run was interrupted** — re-run the same command. The state file resumes the
  pending audit/fix pass. Pass `--allow-dirty` if the fixer left source edits.
- **You want to start over** — remove `audit/` (or move it aside) and re-run.
