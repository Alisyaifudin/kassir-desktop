### Cart writes fail silently and rewrite the entire draft on every edit

- **Slug:** `cart-flush-silent-and-whole-draft`
- **Severity:** high
- **Category:** correctness
- **Status:** fixed
- **Report:** [iterations/001/report-03-cart-flush-silent-and-whole-draft.md](./iterations/001/report-03-cart-flush-silent-and-whole-draft.md)
- **Files:** `src/services/transaction/live.ts`, `src/pages/Pos/page.tsx`, `src/lib/constants.ts`, `src/lib/log.ts`

The POS cart is persisted by rewriting every row of the draft 100 ms after each edit, and `flush` swallows failures into `Effect.logError` while callers use bare `Effect.runFork`. A failed write is invisible in the UI and absent from the Tauri log, so a cart that looks saved can vanish on crash/reload; the rewrite is also O(lines + discounts) statements per keystroke.

### Every mutation re-reads the whole aggregate from SQLite instead of patching the ref

- **Slug:** `hydrate-per-mutation`
- **Severity:** medium
- **Category:** performance
- **Status:** partial
- **Report:** [iterations/001/report-09-hydrate-per-mutation.md](./iterations/001/report-09-hydrate-per-mutation.md)
- **Files:** `src/services/product/live.ts`, `src/services/extra/live.ts`, `src/services/method/live.ts`, `src/services/money/live.ts`, `src/services/cashier/live.ts`, `src/services/record/live.ts`

Most services answer every write with `yield* hydrate()`, re-selecting the entire aggregate from SQLite (product reloads six tables, 20 call sites) and replacing every object in its `SubscriptionRef`. Cost scales with catalogue size, destroys referential stability for memoised lists, and diverges from the documented "write backend then update the ref" pattern that `CashierLive` already follows.
