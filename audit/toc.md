### `integer` / `numerish` can never reject, so a malformed `?page=` renders an empty list and a malformed `?start=` crashes the screen

- **Slug:** `integer-and-numerish-zod-helpers-never-reject`
- **Severity:** medium
- **Category:** correctness
- **Status:** fixed
- **Report:** [iterations/007/report-04-integer-and-numerish-zod-helpers-never-reject.md](./iterations/007/report-04-integer-and-numerish-zod-helpers-never-reject.md)
- **Files:** `src/lib/utils.ts`, `src/pages/Product/use-list-state.ts`, `src/pages/Product/page.tsx`, `src/pages/Record/Search/use-range.tsx`, `src/pages/Money/use-range.tsx`, `src/components/Calendar.tsx`, `src/hooks/use-scroll.ts`

`integer` and `numerish` in `src/lib/utils.ts` are written with `||` instead of `&&`, so the "must be a number / a whole number" rule is unreachable: `integer.parse("abc")` succeeds and yields `NaN`, and `numerish` accepts `""` as `0`. Five URL parsers trust them, and the result is observable: `#/products?page=abc` renders an empty list with a `NaN/NaN` footer and a live "previous page" button, and `#/records/search?start=3.7` throws `RangeError` out of `Temporal.Instant.fromEpochMilliseconds` into the route error boundary — the `.catch(default)` fallback was written for exactly this and never fires.

### `record.set.payCredit` settles a debt with no amount and no state check — the only money write in `record` with no server-side guard

- **Slug:** `paycredit-has-no-amount-or-state-guard`
- **Severity:** medium
- **Category:** correctness
- **Status:** fixed
- **Report:** [iterations/007/report-01-paycredit-has-no-amount-or-state-guard.md](./iterations/007/report-01-paycredit-has-no-amount-or-state-guard.md)
- **Files:** `src/services/record/live.ts`, `src/pages/Record/Item/z-Detail/z-Debt/use-debt.ts`, `src/pages/Record/Item/z-Detail/z-Debt/index.tsx`, `src/services/record/index.ts`

`payCredit` writes `record_pay`, `record_rounding` and `record_paid_at` from caller input, checking only that the numbers are finite and that `pay >= 0`. Settling is what removes a record from the debt list (`WHERE record_credit_at IS NOT NULL AND record_paid_at IS NULL`), so an underpayment clears the debt with the shop short, and a call on a cash sale silently rewrites that sale's payment and re-stamps its paid date. Every other write path in `record/live.ts` validates its boundary (`price < 0`, `unit`, `qty`, `NaN`, blank name); this one is enforced only by the dialog's own `required.gt(pay)` check.
